# RAG-VERGE: reproducibility package

This repository contains the source code, experiment definitions, compact run
results, and analysis outputs for **RAG-VERGE**, an offline
retrieval-guided LLM policy-design workflow for vehicular edge task scheduling.

The experiments couple SUMO-generated Dubai Downtown mobility with OMNeT++,
INET, and Simu5G. The LLM proposes bounded policy parameters offline; runtime
scheduling is deterministic. The paper and code explicitly report the limits
of the current evaluation, including the single map, modeled rather than
validated handover interruption, and small held-out adaptive sample.

## Packet-telemetry follow-up (16 October 2026)

The latest follow-up replaces free server-state access for deployable controls
with timestamped UDP queue reports and restricts task generation to recorded
vehicle activity. It adds Power2, age-aware and FreshPower2 dispatch, coefficient
ablations, four immutable result datasets (308 runs), and seven plot sets.
FreshPower2 improves the mean over Power2 in nine of twelve cells, but the
small paired samples do not establish statistical superiority or a separate
criticality-boost benefit. The planned full scaling matrix is incomplete.
This follow-up contains fixed policies and makes no additional LLM benefit claim.

See [completed packet-telemetry experiments](research/omnet/v2x_model/PACKET_TELEMETRY_RESULTS.md)
for design, caveats, replay commands, and [the audited report](research/omnet/v2x_model/analysis/packet_telemetry_v1/REPORT.md)
for all findings. Run `python3 research/omnet/v2x_model/analyze_packet_telemetry.py`
to regenerate the tables and PNG/SVG figures from the included compact data.

## Repository contents

- `research/omnet/v2x_model/src/`: OMNeT++/Simu5G task and edge-server model.
- `research/omnet/v2x_model/*.py`: mobility preparation, experiment runners,
  RAG/LLM policy search, and analysis scripts.
- `research/omnet/v2x_model/scenario/dubai/`: archived SUMO map/trajectory
  inputs used for the reported mobility seed.
- `research/omnet/v2x_model/scenario/generated/`: the final static study's
  per-cell configuration and CSV/JSON results, plus RAG portfolio, fixed
  telemetry ablation, and reflection experiment configurations and results.
- `research/omnet/v2x_model/analysis/`: processed tables and figures for the
  final static, adaptive portfolio, and ablation studies.

Large OMNeT++ scalar/vector/index traces (`.sca`, `.vec`, `.vci`), transient
logs, compiled libraries, and simulator installations are not versioned. The
compact per-run JSON/CSV outcomes and processed results reported in the paper
are included. Full raw simulator traces can be regenerated by rerunning the
experiments.

## Software environment

The reported software versions are OMNeT++ 6.4.0, INET 4.7.0, Simu5G 1.8.0,
and SUMO. The repository does not redistribute these third-party tools. Install
them under `research/omnet/headless/omnetpp-6.4.0`,
`research/omnet/headless/inet-4.7.0`, and
`research/omnet/headless/simu5g-1.8.0`, respectively, following their official
installation instructions. Python analysis uses `matplotlib` and `numpy`;
SUMO's Python tools must be available through `SUMO_HOME`.

Build the model from the repository root:

```sh
bash research/omnet/v2x_model/build.sh
```

## Reproduce the completed static study

The paper's static baseline contains 1,500 packet-level runs: four vehicle
counts, five RSU counts, three operating conditions, five policies, and five
paired network seeds. Run the full matrix with:

```sh
.venv/bin/python research/omnet/v2x_model/run_final_packet_study.py \
  --area downtown \
  --vehicles 25 75 150 300 \
  --rsus 2 4 6 8 10 \
  --total-edge-rate 320 \
  --seeds 5 \
  --study-tag FinalStaticRadioKpiV1
```

The script prints overall progress and an ETA, writes a study manifest, and
produces per-cell CSV/JSON outcomes and analysis plots. The archived static
results are already included; rerunning the 1,500 simulations is optional.

## Reproduce the adaptive studies

Install and start Ollama, then fetch the model used for the offline proposal
step:

```sh
ollama pull llama3.1:8b
```

The archived adaptive experiment uses training seeds 0--2 and held-out seeds
3--4 across 75/150 vehicles, 2/6/10 RSUs, and burst/failure conditions. The
run scripts and saved manifests record the candidate profiles and evaluated
results. To rerun the RAG portfolio after reproducing or retaining the static
results:

```sh
.venv/bin/python research/omnet/v2x_model/run_rag_portfolio_study.py \
  --study-tag RagPortfolioV2Telemetry \
  --vehicles 75 150 --rsus 2 6 10 \
  --conditions burst failure \
  --train-seeds 0 1 2 --test-seeds 3 4 \
  --provider ollama --model llama3.1:8b
```

The fixed telemetry portfolio and multi-generation reflection have separate
runners and separately saved results. They are ablations, not evidence that
LLM-guided search consistently outperforms conventional policy tuning.

## Data and interpretation

The final static data are stored in `research/omnet/v2x_model/scenario/generated/`
with the `FinalStaticRadioKpiV1` prefix. Adaptive runs use distinct prefixes
and manifests, so result sets are not mixed or overwritten. Analysis scripts
in `research/omnet/v2x_model/analyze_kpis.py` and
`research/omnet/v2x_model/analyze_rag_portfolio.py` produce the processed
tables and plots.

The results are simulator evidence for the stated configuration, not a field
deployment claim. Literature methods are discussed in the manuscript but are
not all reimplemented as common-environment baselines. See the manuscript's
Threats to Validity section before interpreting the reported comparisons.
